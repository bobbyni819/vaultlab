# Readiness Ladder

`readiness.py` defines the deterministic promotion gate for subpanel readiness.

The ladder is monotonic:

1. `DISPLAY_EXISTS`
2. `PROVENANCE_VERIFIED`
3. `GEOMETRY_QA_PASSED`
4. `DECK_READY`
5. `FAILED`

Promotion requires evidence at each rung. Provenance must be non-empty, free of placeholder markers, and paired with a passing coverage audit. Geometry readiness additionally requires a passing layout sidecar audit. Deck readiness additionally requires a passing panel audit.

Placeholder markers are deliberately simple string checks: `record what was`, `todo`, `<fill`, `autogenerated`, `tbd`, `fixme`, and `xxx`. The gate is deterministic and does not inspect files itself.

Lineage: CONCEPT from the dogfood-identified trust-by-assertion failure mode, implemented as a planning-contract readiness gate.
